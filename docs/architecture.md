## System Overview

Nozle is a **usage-based billing platform** built on top of Lago, with additional features for:
- LLM cost tracking and margin intelligence
- Real-time usage updates via WebSocket
- Entitlement-based feature gating
- Atomic credit deduction

### Three-Layer Architecture

```
┌─────────────────────────────────────────────────────────┐
│                   Application Layer                      │
│  ┌──────────────────────────────────────────────────┐   │
```

## Component Architecture

### 1. Engine (Go) - Core Service

**Location**: nozle/engine

**Responsibilities**:
- API endpoint handling
- Usage event tracking
- Entitlement checks
- LLM cost calculation
- Margin intelligence
- Cache management
- Real-time event broadcasting

**Key Packages**:

```
engine/
├── cmd/
│   └── server/          # Entry point (main.go)
├── internal/
│   ├── api/             # HTTP handlers
│   │   ├── router.go              # Route definitions
│   │   ├── can_handler.go         # Entitlement checks
│   │   ├── check_deduct_handler.go# Credit deduction
│   │   ├── customer_handler.go    # Customer mgmt
│   │   ├── plans_handler.go       # Plan fetching
│   │   ├── checkout_handler.go    # Stripe checkout
│   │   ├── margin_handler.go      # Margin analytics
│   │   └── proxy_handler.go       # LLM proxy
│   ├── billing/         # Lago API integration
│   ├── cache/           # Redis cache layer
│   ├── costengine/      # LLM cost models
│   ├── margin/          # Margin calculation
│   ├── realtime/        # Centrifugo integration
│   ├── store/           # Data access
│   │   ├── postgres/    # PostgreSQL stores
│   │   └── clickhouse/  # ClickHouse stores
│   ├── tasks/           # Background jobs
│   └── config/          # Configuration
└── migrations/          # Database migrations
```

**External Dependencies**:
- Lago API (http://localhost:3000)
- PostgreSQL (billing data)
- ClickHouse (margin events)
- Redis (cache + task queue)
- Centrifugo (WebSocket)

### 2. SDKs (TypeScript)

**Location**: nozle/nozle-js

#### @nozle-js/react (Client SDK)

**Purpose**: Client-side billing UI

**Key Exports**:
- `BillingProvider` - Context provider
- `useCan(feature)` - Entitlement hook
- `useUsage(metric)` - Real-time usage
- `usePlan()` - Current plan
- `usePlans()` - Available plans
- `useCheckout()` - Stripe checkout
- `PricingTable` - Pre-built pricing UI
- `UsageMeter` - Usage visualization
- `PlanBadge` - Current plan display

**Data Flow**:
```
Component → useCan() → Engine API → Cache → PostgreSQL
                                       ↓
Component ← WebSocket ← Centrifugo ← Engine
```

#### @nozle-js/node (Server SDK)

**Purpose**: Server-side tracking and API client

**Key Exports**:
- `Nozle` - Main client class
- `nozle.track()` - Track usage
- `nozle.can()` - Check entitlement
- `nozle.checkAndDeduct()` - Atomic credit deduction
- `nozle.customers.upsert()` - Customer management
- `nozle.plans()` - Fetch plans
- `nozle.checkout()` - Create checkout session
- `nozle.margin.*` - Margin analytics
- `wrapOpenAI()` - Auto-track OpenAI
- `wrapAnthropic()` - Auto-track Anthropic

**Data Flow**:
```
App API Route → nozle.track() → Engine /api/v1/events
                                   ↓
                           Kafka → Lago API → PostgreSQL
                                   ↓
                              ClickHouse (margin events)
```

## Technology Stack

### Backend (Engine)
- **Language**: Go 1.26+
- **Framework**: Chi (HTTP router)
- **Database**: PostgreSQL (Lago's schema)
- **Analytics**: ClickHouse (margin events)
- **Cache**: Redis
- **Task Queue**: Asynq (Redis-backed)
- **Real-time**: Centrifugo (WebSocket server)
- **Billing**: Lago (Open-source metering/billing)
- **Messaging**: Kafka/Redpanda

### Frontend (SDKs)
- **Language**: TypeScript
- **Framework**: React 19+ (client SDK)
- **Runtime**: Node.js 18+ (server SDK)
- **Build**: tsup (bundler)
- **Payments**: Stripe

### CLI
- **Language**: TypeScript
- **Framework**: Commander.js
- **Prompts**: prompts library
- **Template**: Next.js 15 App Router

## Data Flow

### 1. Usage Tracking Flow

```
User App API Route
    │
    │ nozle.track(customerId, metric, properties)
    ▼
@nozle-js/node Client
    │
    │ POST /api/v1/events
    ▼
Engine API
    │
    ├─ 1. Validate API key (cache/DB)
    │
    ├─ 2. Resolve customer (cache/DB)
    │
    ├─ 3. Enrich with cost data (if LLM event)
    │
    ├─ 4. Publish to Kafka
    │      │
    │      ▼
    │   Lago API (consumes Kafka)
    │      │
    │      ▼
    │   PostgreSQL (billing events)
    │
    └─ 5. Store margin event → ClickHouse
       │
       └─ 6. Broadcast real-time update → Centrifugo
              │
              ▼
          Client receives WebSocket update
              │
              ▼
          useUsage() hook re-renders
```

### 2. Entitlement Check Flow

```
React Component
    │
    │ useCan('feature_code')
    ▼
@nozle-js/react Hook
    │
    │ POST /api/v1/can
    ▼
Engine API
    │
    ├─ 1. Check entitlement cache (Redis)
    │      └─ HIT → Return cached result
    │      └─ MISS ↓
    │
    ├─ 2. Query PostgreSQL
    │      └─ Get customer's subscription
    │      └─ Get plan's charges
    │      └─ Check feature entitlement
    │
    ├─ 3. Cache result (Redis, 5min TTL)
    │
    └─ 4. Return { allowed, reason, used, limit, margin }
       │
       ▼
    Component conditionally renders
```

### 3. LLM Auto-Capture Flow

```
User App
    │
    │ const openai = wrapOpenAI(new OpenAI(), nozle, {...})
    ▼
@nozle-js/node Wrapper
    │
    │ openai.chat.completions.create({...})
    ▼
OpenAI API
    │
    │ Returns response with usage: { input_tokens, output_tokens }
    ▼
Wrapper Intercepts
    │
    ├─ Extract: model, tokens, latency
    │
    └─ Auto-call: nozle.track(customerId, 'llm_tokens', {
          model, input_tokens, output_tokens, latency_ms
       })
       │
       ▼
    Engine calculates cost from model pricing
       │
       ▼
    Stores margin event: revenue - cost
```

## Deployment Architecture

### Development (Local)

```
localhost:3000  → Lago API
localhost:8080  → Nozle Engine
localhost:5432  → PostgreSQL
localhost:6379  → Redis
localhost:9000  → ClickHouse
localhost:19092 → Kafka (Redpanda)
localhost:8001  → Centrifugo
```


### Production

```
api.nozle.app    → Engine (Cloud Run)
core.nozle.app   → Lago API (Cloud Run)
ws.nozle.app     → Centrifugo (Cloud Run)

PostgreSQL       → Cloud SQL
Redis            → Memorystore
ClickHouse       → GKE (StatefulSet)
Kafka            → Cloud Pub/Sub or Confluent Cloud
```

**Load Balancing**:
- Engine: Auto-scaling (1-10 instances)
- Lago: Auto-scaling (1-5 instances)

**Caching Strategy**:
- API keys: Redis, 1hr TTL
- Entitlements: Redis, 5min TTL
- Cost models: In-memory + Redis, 1hr TTL
- Customers: Redis, 30min TTL

## Security Model

### API Key Types

| Type | Prefix | Usage | Permissions |
|------|--------|-------|-------------|
| Secret | `sk_` | Server-side | Full access (track, can, margin) |
| Public | `pk_` | Client-side | Read-only (plans, public data) |

### Authentication Flow

```
Request with X-Nozle-Key header
    │
    ├─ 1. Check API key cache (Redis)
    │      └─ HIT → Validate + get organization
    │      └─ MISS ↓
    │
    ├─ 2. Query PostgreSQL
    │      └─ Validate key exists
    │      └─ Get associated organization
    │
    ├─ 3. Cache API key (Redis, 1hr)
    │
    └─ 4. Attach org context to request
       │
       └─ Proceed to handler
```

### Authorization

**Scope-based**:
- Secret keys: Can track usage, check entitlements, access margin data
- Public keys: Can only read public data (plans, etc.)

**Org-scoped**:
- All queries filtered by `organization_id`
- No cross-org data leakage

**Rate Limiting** :
- Per API key
- Redis-backed sliding window

## Scalability Considerations

### Bottlenecks

1. **PostgreSQL** (Lago's billing DB)
   - Heavy writes during usage tracking
   - Mitigated by Kafka async processing

2. **Cache Stampede**
   - Multiple requests for expired cache
   - Mitigated by cache refresher background job

3. **ClickHouse Inserts**
   - Margin events can be high-volume
   - Mitigated by batching 

### Scaling Strategy

1. **Horizontal Scaling**
   - Engine is stateless (scales to N instances)
   - Lago API is stateless (scales to N instances)

2. **Cache Layer**
   - Redis for hot data
   - In-memory for cost models

3. **Async Processing**
   - Kafka decouples event ingestion from billing
   - Asynq for background tasks

## Error Handling

### Retry Strategy

**Usage Tracking**:
- Network errors: Retry 3x with exponential backoff
- 5xx errors: Retry
- 4xx errors: No retry (log and drop)

**Entitlement Checks**:
- Network errors: Fail open (allow temporarily)
- 5xx errors: Fail open
- 4xx errors: Fail closed (deny)

**LLM Proxy**:
- Provider down: Return 502, don't charge
- Timeout: Return 504, charge based on estimated tokens
